2Problem & Opportunity

AI initiatives are siloed, difficult to prioritize objectively, and lack a unified governance model. That leads to duplicated efforts and suboptimal resource allocation. Specifically:

  • Siloed tracking: each business unit keeps its own list of AI ideas. Two teams can pursue nearly the same use case without knowing it.
  • No common scoring: steering committees compare slide decks, not comparable scores. There is no shared rubric for feasibility, value, data readiness, or security.
  • No portfolio view: leadership cannot see the full set of AI investments on one screen, which initiatives overlap, or which ones are stalled.
  • Inconsistent governance: security and compliance checks happen at different stages, or not at all. Problems surface late, after budget has been committed.

Who is affected

  • Enterprise Architecture and Strategy (no consolidated view)
  • Steering committees (no way to compare initiatives side by side)
  • Business-unit AI leads (no clear intake path)
  • Security and compliance (late visibility into AI risk)
  • Finance (cannot track AI portfolio spend)
  • Domain Squads (no standard way to propose and track work)
Cost of inaction (do-nothing baseline)
Without a shared prioritization process, roughly 15% of portfolio spend goes to low-value or redundant initiatives ESTIMATE that would have been deprioritized with better visibility. On a $2M annual AI portfolio ESTIMATE, that is about $300K a year in misallocated capital. Add duplicated vendor contracts, delayed high-value work, and governance gaps that only get worse as AI use cases multiply.

3Strategic Alignment

This falls under Digital Transformation & Operational Excellence and lines up with Veralto Enterprise System (VES) principles:

  • Customer-centricity: the scoring rubric evaluates every initiative against real customer and business impact, not who presents it best.
  • Continuous improvement / lean: self-serve intake and automated scoring remove manual steps from the evaluation cycle. Committees spend time reviewing, not collecting information.
  • Quality and problem-solving: data readiness, security, and compliance checks are part of the intake form, not an afterthought.
  • Standard work: every AI initiative follows the same path from submission to scoring to steering review.

4Proposed Solution & Scope

Build a web portal on Azure where teams submit AI initiative proposals, a scoring engine evaluates them, and leadership sees the results on an interactive Prioritization Matrix. The portal runs a hub-and-spoke governance model: centralized standards, decentralized execution through Domain Squads.

Architecture

ComponentTechnologyPurpose
FrontendVanilla JavaScript, CSS, HTMLModular, no framework overhead. Runs as an Azure Static Web App.
IdentityAzure Entra ID (SSO)Enterprise login and role-based access
Data storeAzure Cosmos DBStores initiative records and scoring data. Schema-flexible.
HostingAzure Static Web AppsLow-cost hosting with built-in CI/CD

Core capabilities

  • Self-serve intake: business units submit AI use cases through a guided form. All scoring dimensions are captured upfront.
  • Scoring engine: each initiative is rated on technical feasibility, business value, data readiness, and security/compliance. The engine produces a composite score and places the initiative in a quadrant.
  • Prioritization Matrix: a value-vs-feasibility scatter plot that sorts initiatives into four categories: Strategic Investments, Quick Wins, Incremental Improvements, or Reconsider. You can see the portfolio balance at a glance.
  • Domain Squad views: each squad sees its own pipeline and scores. The Hub sees the full portfolio across all squads.
  • Self-healing state management: schema versioning and coordinate logic in the app automatically patch data conflicts, so the portal does not need constant maintenance.

Governance framework

Hub-and-Spoke: the Hub (Enterprise Architecture & Strategy) owns the tooling, scoring standards, and portfolio oversight. Domain Squads, led by business units, own execution. They run their own AI use cases but follow the same scoring rubric and intake process.

In scope

  • Initiative intake portal with guided submission
  • Scoring engine (feasibility, value, data, security)
  • Prioritization Matrix (interactive scatter plot)
  • Portfolio dashboard with filtering and drill-down
  • Domain Squad pipeline views
  • Azure Entra ID SSO integration
  • Cosmos DB backend with schema versioning
  • Role-based access (Hub admin, Squad lead, Viewer)

Out of scope (future phases)

  • Automated ML model deployment or MLOps integration
  • Financial system or ERP integration
  • Vendor procurement workflow automation
  • Advanced analytics or predictive portfolio modeling
  • Mobile-native application

10Resource & Organizational Impact

  • People: 1-2 developers (vanilla JS / Azure), an architecture sponsor, Domain Squad champions for the pilot, and a security/compliance reviewer for Entra ID and the data model.
  • Process change: proposals move from ad-hoc emails and slide decks to a portal submission. Steering committees see pre-scored, ranked portfolios instead of raw pitches. Domain Squads get a self-service pipeline view.
  • Change management: onboarding sessions for each Domain Squad. Executive communications that position the portal as an enabler, not a gate. Quick-reference guides and in-app help.
  • Skills: minimal for end users. Squad leads need a short walkthrough on submission and scoring. Hub admins need training on rubric configuration and portfolio management.
